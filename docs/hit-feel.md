# 打击感规范（Hit Feel）

《生态争夺》攻击、受击、死亡的手感参数与实现方法。数值来自网站实验室（`web/src/lab.ts`）里已经调好的实现，可以直接搬进 Phaser / PixiJS 正式游戏。设计依据是 aseprite-ai-artist 知识库的 `rules/44-attacks-and-impacts` 与 `rules/81-impacts-and-game-feel`（MIT），以及 Celeste、Vlambeer 等的业界惯例。

> 在线演示：网站 → 实验室 → "攻击"面板勾选/取消"攻击节奏 + 打击感"对比；把"速度"调到 0.25× 可以逐帧看清。

## 1. 原则

一次有分量的攻击来自三件事，而不是更多的帧：

1. **反方向蓄力**：出手前先往反方向收，停住让玩家看清（敌方的"预告"）。
2. **极短的出击**：出击只占 1 帧左右（约 50ms），配一道残影弧线。
3. **命中时停顿**：命中帧多停一会儿，同时全局"定格"几十毫秒，再接火花、后退、闪白。

另外两条规则：**伤害必须落在命中帧上**（不是动画开始时），**收招比出击慢**。

## 2. 攻击时序

### 2.1 AI 手改攻击（当前默认素材，9 帧）

| 帧 | 阶段 | 普通 | 重型（大型单位） | 画面内容 |
| --- | --- | --- | --- | --- |
| 0 | 站立 | 100ms | 100ms | 原姿势 |
| 1 | 蓄力开始 | 110ms | 110ms | 头部后收 1×m px，身体压低 5% |
| 2 | 蓄力停顿 | **200ms** | **280ms** | 头部后收 2×m px，压低 10%，后仰 |
| 3 | 出击（残影） | **50ms** | **50ms** | 前冲 3×m px，拉伸 14%，亮色残影弧 |
| 4 | **命中** | **140ms** | **170ms** | 前冲 4×m px，前肢伸出 ← 伤害、火花、定格挂在这一帧 |
| 5 | 跟随 | 80ms | 80ms | 回收 1px |
| 6 | 收招 | 90ms | 110ms | 回到 +1×m px |
| 7 | 回弹 | 50ms | 50ms | 比原位多退 1px（overshoot） |
| 8 | 站立 | 120ms | 120ms | 原姿势 |

总长：普通约 0.94s，重型约 1.07s。`m` 是幅度系数，按画布：32px = 1.0（小型/微型再 ×1.2），48px = 1.3，64px = 1.6。

正面（朝向镜头）没有横向空间：蓄力改为"后仰缩小"，出击改为"放大并下移"（扑向镜头），不画残影（会盖住脸）。背面：蓄力下沉，出击向上拉伸。

每帧时长都写在图集 JSON 的 `frames[name].duration`，命中帧序号在 `meta.unit.hit["attackhand_<方向>"]`。

### 2.2 没有手改帧时（PixelLab 原版 6 帧）

自动找出"向面朝方向伸得最远"的一帧作为命中帧 h，按下面的规则重排时长：

| 帧 | 时长 |
| --- | --- |
| 0 | 120ms |
| 1 … h−2 | 110ms |
| h−1 | 50ms |
| **h（命中）** | **160ms** |
| h+1 … 末帧前 | 90ms |
| 末帧 | 120ms |

原版画面里没有前冲，代码在命中帧前后 ±140ms 内把精灵朝面朝方向推 4px（三角形曲线）。

### 2.3 攻击循环

- 每次攻击**单独播放一遍**（不循环），播完回到待机。
- 两次攻击之间冷却 0.45–0.75s（随机，避免整齐划一）。
- 一旦开始出手就播完，即使目标中途死亡或离开（避免动作被截断）。

## 3. 命中反馈

| 效果 | 参数 | 说明 |
| --- | --- | --- |
| 定格（hitstop） | 普通 **70ms**，大型攻击者 **110ms** | 攻击方和受击方**同时**冻结动画与移动；上限不超过约 200ms |
| 受击闪白 | **100ms** | 叠加一层同帧精灵，加法混合（Phaser 可用 `setTintFill(0xffffff)`），透明度从 1 线性降到 0 |
| 受击抖动 | 闪白期间每帧 ±1px 横向随机 | |
| 击退 | 共约 **3px**，持续 120ms，速度线性衰减 | 方向：攻击者 → 受击者；撞到不可走的地形就停 |
| 火花 | 8 道射线，普通半径 6px / 160ms，重击 9px / 220ms、线宽 2px | 前 35% 时间纯白，之后金色 `#ffd36b`，同时淡出到 40%；位置在双方连线中点、受击者身高 1/4 处 |
| 震屏 | 仅大型单位命中：**140ms**，每帧 ±2px | 只抖摄像机，不动单位 |

不受光照影响的层：火花、血条、阵营圈、Zzz 画在光照之上（夜里也清楚）。

## 4. 死亡

AI 手改的死亡动画（7 帧，所有单位都有）：

| 帧 | 时长 | 画面 |
| --- | --- | --- |
| 0 | 90ms | 被致命一击后退 2×m px |
| 1 | 110ms | 踉跄，压低 5%，倾斜 6° |
| 2 | 100ms | 腿软，压低 15%，倾斜 12° |
| 3 | 80ms | 倒下，压低 28%，倾斜 18° |
| 4 | 70ms | 着地，压低 40%，倾斜 22°，下沉 1px |
| 5 | 70ms | 弹一下 |
| 6 | 500ms | 静止 |

播完后由代码**淡出 800ms** 再移除。蜂群类改为"从空中掉落"。死亡动画始终按设定的时长播放，不受打击感开关影响。

## 5. 休息

不单独出图：待机动画以 35% 速度播放，头顶加浮动的 "Zz"（上下 ±1.5px，周期约 3s）。休眠时段读物种表的"休眠时段/时长"列：夜晚、白天（11–15 点）、全天候随机。

## 6. 在引擎里实现

```ts
// 伪代码：一次攻击
startAttack(unit, target) {
  const key = `attackhand_${unit.dir}`;           // 没有则回退到 attack_<dir>
  const frames = atlas.animations[key];
  const hit = atlas.meta.unit.hit[key];
  playOnce(unit, frames, frames.map(f => atlas.frames[f].duration));
  onFrame(unit, hit, () => {
    const heavy = unit.sizeClass === "large";
    hitstop([unit, target], heavy ? 110 : 70);    // 两边一起冻结
    target.damage(unit.dmg);
    target.flashWhite(100);
    target.knockback(dirFrom(unit, target), 3, 120);
    spawnSpark(midpoint(unit, target), heavy);
    if (heavy) camera.shake(140, 2);
  });
  onComplete(unit, () => unit.cooldown = 0.45 + Math.random() * 0.3);
}
```

- **Phaser 3**：hitstop 用 `sprite.anims.pause()` + `scene.time.delayedCall(ms, resume)`；闪白用 `setTintFill(0xffffff)` 再 `clearTint()`；震屏 `cameras.main.shake(140, 0.002)`。
- **PixiJS**：参考 `web/src/lab.ts` 的 `attack()`、`hit()`、`kill()`、`drawSparks()`、`draw()`；时长与回退规则在 `web/src/data.ts` 的 `resolve()`、`durations()`。

## 7. 调参建议

- 觉得"肉"：先加命中帧停顿和 hitstop，而不是加帧。
- 觉得"拖"：缩短蓄力停顿（玩家单位可以缩到 50ms 以内），收招不要短于出击。
- 上百单位同屏时，火花和震屏要限流：同一帧最多 N 个火花，震屏只给离镜头近的大型单位。
