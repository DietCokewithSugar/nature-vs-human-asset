# 3D 路线试验：Tripo 生成 → 像素渲染（洞熊）

流程：PixelLab 像素形象 →（Tripo 图生图）平滑写实参考图 → Tripo P2 生成 3D 模型 → 检查能否绑骨骼 → 四足骨骼（rig v2.5）→ 行走动作 `preset:quadruped:walk`
→ `scripts/render3d`：无头 three.js 正交渲染 8 方向 → `pixelize.py` 缩成 64px，套用 PixelLab 形象的调色板，加描边。
待机、攻击、死亡三个动作是在骨骼上程序化做的，Tripo 的四足预设动作只有行走。

- `cave_bear_pixellab_vs_3d.png` / `.gif`：同一只洞熊，PixelLab 版和 3D 版逐行对比。
- 模型和中间文件：`units/nature_ice_cave_bear/tripo/`、`units/nature_ice_smilodon/tripo/`。

## 结论（2026-11-09）
- **3D 的优点**：8 个方向绝对一致；行走 8 帧且步态自然；体型可以按真实比例统一缩放。
- **3D 的不足**：画面偏软，缺少手绘像素的笔触和锐利边缘；程序化攻击的表现力远不如 PixelLab 结合版（人立咆哮、扑击）。
- **踩过的坑**：
  1. 直接拿像素图生成 3D，会把像素台阶当成几何，得到体素一样的方块模型。必须先用图生图转成平滑参考图。
  2. 不做"能否绑骨骼"检查就绑骨骼，会默认绑成两足骨架，之后四足动作无法套用。
  3. 迈步、前倾这类姿势的参考图，可能让四足骨骼绑错，剑齿虎第一次就是这样。参考图要用中立站姿。
- **费用**：一个物种走完正确流程约 145–150 积分（图生图 5 + P2 模型 110 + 绑骨骼 25 + 行走 10），不含试错。
